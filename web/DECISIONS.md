# Decisions made for you

One line each: what I chose, and why. Newest at the bottom of each section.

## Repo and branch

- **Built in `Claude_code_mobile`, not `algorithm-health-companion`.** This session only has access to this repo; all work is in a new `web/` folder plus `SPEC.md` at the root, so it can be copied to another repo wholesale.
- **There is no Android code here.** The existing code is `prosper-scout/` (a Python app). I did not modify, move or delete it.
- **Branch is `claude/new-session-5v06dn`, not `web-test`.** The session I run in is only permitted to push to that branch; rename or cherry-pick it to `web-test` if you want the name from the prompt. No PR opened, nothing pushed to `main`, nothing deployed.

## Scaffold (milestone 1)

- **No router library; a 40-line path router.** Three fixed routes do not need a dependency.
- **`npm run build` copies `index.html` into `scan/`, `review/`, `compare/` and `404.html`.** Hosting is undecided, and this makes the three routes work on any plain static host without rewrite rules.
- **`VITE_BASE` env var sets the base path (default `/`).** Needed if the site ends up under a sub-path such as GitHub Pages.
- **Fonts are self-hosted from the `@fontsource` npm packages, not loaded from Google Fonts.** Keeps the app to "its own files" only, so no tester IP goes to a font CDN.
- **`DECISIONS.md` and `NIGHT_LOG.md` are not empty at the scaffold commit.** The prompt asks for them to be kept up to date from the start; an empty file would have been untrue.

## Summary file and fixtures (milestone 2)

- **`accounts` entries are `{ "name", "views" }`.** The spec says "handle or channel name, view count" without naming keys; these are the shortest honest names.
- **`rangeStart` and `rangeEnd` are days (`YYYY-MM-DD`, UTC), not times.** The tester is told a "date range"; exact times of viewing would be more than the spec says leaves the device.
- **`totalViewEvents` counts every view event in the range, attributed or not.** So `sum(accounts.views) + unattributedEvents = totalViewEvents`, and the validator checks it.
- **The validator rejects unknown fields rather than ignoring them.** A summary with extra data in it is exactly what the privacy rule is meant to stop.
- **Fixtures are generated by `scripts/make-fixtures.mjs` (seeded, fixed dates).** Small zips are committed; the two large ones (210,000 events each, ~6 MB zipped, ~55 MB unzipped) are generated on first `npm test` and git-ignored to keep the repo small.
- **Added a "second scan" fixture per app (`*-normal-second.zip`).** Not in the spec's list, but `/compare` cannot be tried with fixtures without one.
- **Fixture names carry a topic (`example_memes_account_03`, "Example Coding Channel 01").** Still obviously fake, but lets the classification step be tried end to end.

## Adapters (milestones 3 and 4)

- **Zip reader is `@zip.js/zip.js`.** It reads the zip's index and then decompresses only the named entries, in chunks, so neither the zip nor any entry is ever held whole in memory.
- **Big JSON files are read with my own small streaming reader (`src/lib/json-stream.ts`)** that hands over one record at a time. A stock `JSON.parse` would need the whole 50 MB+ history as one string.
- **zip.js web workers are switched off.** Decompression uses the browser's built-in streaming decompressor; no worker script has to be loaded, which keeps "no network during a scan" simple to prove.
- **The 30-day window counts back from the newest view event in the export, not from today.** An export requested last week should still give 30 days of data.
- **An export with zero view events is a clear error, not an empty summary.** A summary with nothing in it cannot be scored and would only confuse the builder.
- **Records with no readable date are skipped and counted; more than 5% of them stops the scan.** A few odd records are normal in real data; many mean the format is not what I assumed, and guessing would be silent.
- **Two files with the same expected name stop the scan.** I cannot know which one is the right one.
- **YouTube: every watch-history entry with a channel counts, including YouTube Music and adverts that name a channel.** The spec only says to skip entries with no channel; filtering more would be a guess about a format I have not seen.
- **YouTube: a missing `subscriptions.csv` stops the scan.** Without the following list the test's success measure cannot be judged.
- **YouTube: translated Takeout file or column names are not handled.** The scan stops and lists what it found; add the names in `src/adapters/youtube.ts`.
- **Instagram: one of `posts_viewed.json` / `videos_watched.json` is enough; the preview says which was missing.** Someone who watches only reels (or only posts) may have just one.
- **Instagram: the following handle is read from `string_list_data[0].value`, falling back to `title`.** Both shapes are believed to exist depending on export date.
- **Instagram: timestamps must be seconds between 2010 and 2100, else the record is unreadable.** Stops a milliseconds-vs-seconds change from silently producing nonsense dates.
- **Instagram: translated keys (in place of `Author` / `Time`) and exports split over several zips are not handled.** The scan stops and reports the keys or file names it saw.
- **Handles and channel names are kept exactly as written in the export (trimmed only).** Changing case or stripping characters would be guessing.
